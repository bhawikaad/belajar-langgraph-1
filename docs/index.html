Article Creation dengan LangGraph

Folder latihan LangGraph: sebuah pipeline multi-agent yang membuat artikel blog dari satu topik. Beberapa agent LLM bekerja bergantian (membuat outline, menulis, menilai), lalu manusia memberi persetujuan akhir sebelum artikel disimpan sebagai file Markdown.

Input

Satu topik, misalnya Agentic AI in 2027, yang Anda ketik saat program dijalankan.

Output

File output/<topik>-<waktu>.md berisi catatan (topik, outline, prompt gambar cover) lalu artikel akhir.

LLM

ChatOpenAI dari langchain_openai, diarahkan ke OpenRouter lewat .env.

Fitur LangGraph yang dilatih

Conditional edge, loop revisi, checkpointer SQLite, streaming, human-in-the-loop.

Struktur folder

belajar_article_creation/

├── agents/              ← satu class per agent (yang memanggil LLM)

│   ├── generator.py        outline → artikel (+ revisi)

├── graph/
│   ├── state.py         ← ArticleState: data bersama antar node
│   ├── nodes.py         ← fungsi node (tipis, memanggil agent/service)
│   ├── router.py        ← fungsi penentu cabang conditional edge
│   └── workflow.py      ← merakit node + edge menjadi graph

├── models/evaluation.py ← EvaluationResult (output terstruktur evaluator)

Cara memulai

Centang tiap langkah setelah selesai (tersimpan di browser Anda). Perintah ditulis untuk Windows.

  1. Siapkan virtual environment
    python -m venv .venv
    .venv\Scripts\activate
  2. Pasang dependensi
    pip install -r requirements.txt

    Jika muncul CERTIFICATE_VERIFY_FAILED (proxy/antivirus mencegat HTTPS), cara cepat tapi mematikan verifikasi sertifikat: pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org -r requirements.txt. Lebih aman: perbaiki sertifikat Python/jaringannya.

  3. Buat file .env di root proyek dengan isi: 
    # API key OpenRouter Anda (wajib)
OPENROUTER_API_KEY=isi-key-anda
# Nama model di OpenRouter (wajib)
OPENROUTER_MODEL=nama-model-pilihan-anda
# Opsional; default: https://openrouter.ai/api/v1
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
# Opsional; bahasa artikel/outline/feedback. Default: Indonesian
OUTPUT_LANGUAGE=Indonesian

    Tanpa dua variabel wajib itu, import config.settings langsung gagal, sehingga semua yang memakai LLM ikut gagal. File .env sudah di-ignore git.

  4. Jalankan aplikasi
    python main.py

    Yang akan terjadi:

    1. Muncul pertanyaan Silakan masukkan topik artikel:; ketik topiknya lalu Enter (input kosong ditanya ulang, Ctrl+C membatalkan).
    2. Progres tercetak per node, mis. [generator] selesai, mengubah: ['article'].
    3. Graph berhenti di human_review: artikel dan prompt gambar ditampilkan, lalu Anda diminta mengetik y atau n.
    4. y → artikel disimpan ke output/. n → Anda bisa mengetik catatan perbaikan (opsional), lalu artikel ditulis ulang dan Anda ditanya persetujuan lagi, sampai menjawab y.
    5. Di akhir tercetak thread_id dan riwayat checkpoint.
  5. Lihat lagi run lama (tanpa memanggil LLM), memakai thread_id dari output run sebelumnya:
    python main.py <thread_id>
  6. Jalankan tes dari root proyek (tidak ada pytest; tiap file adalah skrip yang mencetak hasil):
    python -m tests.test_human_review
    Tes mana yang memanggil LLM sungguhan?

    Tanpa LLM (agent palsu, cepat): test_router, test_storage, test_checkpointer, test_sqlite_checkpointer, test_streaming, test_human_review.

    Memanggil LLM (butuh .env aktif): test_evaluator, test_generator, test_image_prompt. Ada juga test_conditional_edge dan test_evaluation_model (skrip kecil).

Agents & node

Setiap agent adalah class di agents/ dengan satu method run(state). Node di graph/nodes.py hanya membuat agent lalu memanggil run, jadi logika agent bisa dites tanpa LangGraph. Agent mengembalikan hanya field yang berubah; LangGraph yang menggabungkannya ke state.

LLM

OrchestratorAgent

Membuat outline artikel dari topik.

Membaca: topic
Menulis: outline

Prompt: ORCHESTRATOR_PROMPT

LLM

GeneratorAgent

Menulis artikel Markdown. Jika sudah ada feedback dan draft lama, ia merevisi draft itu.

Membaca: topic, outline, (article, feedback, revision_count)
Menulis: article, revision_count (saat revisi)

Prompt: GENERATOR_PROMPT + GENERATOR_REVISION_PROMPT

LLM

EvaluatorAgent

Menilai artikel (kejelasan, struktur, relevansi, kelengkapan, keterbacaan). Memakai with_structured_output(EvaluationResult) sehingga jawabannya berupa objek score, feedback, approved, bukan teks bebas.

Membaca: article
Menulis: feedback, approved

score dihasilkan tetapi tidak disimpan di state.

LLM

ImagePromptAgent

Menulis prompt gambar cover (bahasa Inggris, tanpa teks di gambar) dari artikel yang sudah disetujui evaluator.

Membaca: topic, article
Menulis: image_prompt

Gambarnya sendiri belum dibuat.

Manusia

human_review_node

Bukan agent LLM. Memanggil interrupt() sehingga graph berhenti dan menunggu jawaban Anda.

Membaca: article, image_prompt
Menulis: human_approved; saat ditolak juga feedback (catatan Anda) dan revision_count (direset 0)

Biasa

Bukan agent. Menulis catatan (topik, outline, prompt gambar) dan artikel ke output/ lewat services/storage.py.

Membaca: topic, outline, image_prompt, article
Menulis: output_path

Konsep LangGraph yang dipakai

      
StateGraph, node, dan edge
        
StateGraph(ArticleState) adalah graph yang berbagi satu state. Node = fungsi
          state → perubahan state. Edge = urutan eksekusi; add_edge(a, b)
          berarti setelah a selalu b. START dan END adalah titik awal dan akhir.

      
Partial update
        
Node tidak perlu mengembalikan seluruh state; cukup field yang berubah. LangGraph menggabungkannya
          ke state (secara default field ditimpa nilai baru).

      
Conditional edge & router
        
add_conditional_edges(node, router, {label: tujuan}): setelah node, fungsi router
          dipanggil dengan state terbaru dan mengembalikan sebuah label; peta menerjemahkan label itu ke node tujuan.
          Tujuan boleh node sebelumnya, itulah cara membuat loop revisi. Counter
          revision_count mencegah loop tanpa akhir.

      
Checkpointer & thread_id
        
Checkpointer menyimpan snapshot state setelah tiap langkah. Di proyek ini dipakai SqliteSaver
          (memory/checkpoints.db), jadi data bertahan setelah program selesai.
          thread_id adalah nama sesi: checkpoint dengan id sama dianggap satu run yang berlanjut.
          get_state_history() membaca semua snapshot.

      
Streaming (stream_mode="updates")
        
stream() menghasilkan item setiap kali sebuah node selesai: {nama_node: field_yang_diubah}.
          Berbeda dengan invoke() yang hanya mengembalikan hasil akhir. stream() tidak
          mengembalikan state akhir; ambil lewat get_state(config).values.

      
Human-in-the-loop: interrupt & Command(resume)
        
interrupt(payload) di dalam node menghentikan graph dan mengirim payload ke pemanggil
          (di stream muncul sebagai item berkunci "__interrupt__"). Pemanggil melanjutkan dengan
          Command(resume=nilai) pada thread_id yang sama; nilai menjadi hasil
          kembalian interrupt(). Wajib ada checkpointer.

        
Penting: saat dilanjutkan, node dijalankan ulang dari baris pertama, jadi jangan taruh
          efek samping sebelum interrupt().

    


    
    

      
Catatan penting

      
Satu thread_id baru per run. Jika thread lama dipakai ulang, nilai lama
        (feedback, revision_count, …) masih ada di state dan terbawa ke run baru, sehingga draft pertama
        bisa salah dianggap revisi. main.py membuat id baru lewat uuid4() setiap dijalankan.

      
Jatah revisi habis = tidak disimpan. Jika evaluator menolak sampai
        MAX_REVISIONS (2) terlampaui, workflow berhenti di END tanpa menyimpan apa pun. Ubah rute
        max_revisions ke save bila ingin draft terakhir tetap tersimpan.

      
Graph selalu berhenti di human_review. Memanggil invoke/stream
        tanpa Command(resume=...) tidak akan sampai ke save. Tes yang menjalankan graph penuh harus melanjutkan dengan
        Command(resume=True).
